# MBS SDK

## Design Catalog Contracts (5C-A)

The additive `CatalogPresetV1` envelope wraps the unchanged `DesignPresetV1`.
It adds localized ru-RU/en-US tags and at least two named composition axes with
localized descriptions. Its `contentDigest` is lowercase SHA-256 of RFC 8785
canonical JSON `{preset, metadata}`. The envelope's format and digest fields are
not included in that hash. New catalog versions use bounded numeric SemVer
without leading zeroes, while frozen legacy version acceptance is unchanged.
These declarations do not prove visual uniqueness;
the 1040-preset render and design review remain separate acceptance gates.

`DesignLibraryV2` describes a data-only ZIP: a manifest, preset envelopes,
PNG previews, NOTICE and optional provenance/license text. Manifest `files`
hashes the exact uncompressed bytes of every resource except the manifest;
`entries` lists preset paths and their same byte hashes. The package digest is
SHA-256 of the RFC 8785 canonical manifest, distinct from a ZIP's transport hash.
Core independently enforces paths, special-file rejection, size/pixel/ratio
limits, exact trusted module versions, asset placeholders and immutable versions.
Archives are validated data, NOT signed or executable packages. No license
Authority key is a catalog signing key. Unknown signature/code fields fail closed.

Generate these three new schemas with
`node scripts/design-catalog-schemas.mjs`; `npm test` checks deterministic output.
They do not replace or edit any frozen v1/v2 schema. Old library-v1 archives need
explicit metadata migration; the host must not invent composition declarations.
`CatalogImportReportV1.scope=offline` only means structural validation: workspace
permissions, conflicts, quotas and CAS are checked by the authenticated Core API.
Rollback creates a new catalog revision and retains exact historical versions;
it is not a rewrite of a site's saved document or published release.

Iteration 5A adds PageDocumentV2, bounded LayoutNodeV2 trees, exact revision refs,
theme/shell/composition contracts, data-only DesignPresetV1/SiteTemplateV1 and a
separate SitePublicConfigV2. Existing v1 schemas are byte-for-byte retained and
checked against accepted hashes. New schemas are generated reproducibly by
`node scripts/builder-schemas.mjs`; `npm test` checks generation drift.

Tree helpers move/insert/duplicate/remove immutable data, reject cycles and
enforce 500 nodes/depth 8. An explicit v1 upgrader creates new data; it does not
rewrite saved v1 revisions or change exact legacy module versions. Semantic
main/slot rules, composed limits, module props, ownership, referenced revisions,
URLs and asset permissions still require independent Core/Runtime validation.
These contracts alone are not a working visual editor, preset catalog or CMS.

Module Engine adds `BuiltinModulePackageV1` and `DraftPreviewV1` as separate,
additive wire contracts. Existing PageDocument v1, ModuleManifest and localization
schemas are unchanged. A built-in package is compiled into the shared renderer;
its digest covers the deterministic source bundle, not a customer-provided URL.
`trust: compiled-in` is not a manufacturer signature or permission to hot-install
third-party JavaScript. Preview envelopes are internal, authenticated, transient,
and never valid public delivery snapshots. Target paths carry their own locale;
previewHref is generated by Core, not editable page props.

The Go `licensing` package contains the public JCS/Ed25519 wire codec, installation
proof formats and state rules. Issuance credentials and commercial entitlement
management remain exclusively in the private Authority. License v1 now requires
key binding, monotonic sequence and an explicit signed online/offline policy.

Public data contracts for MBS Platform. This repository contains no private Go
Core, Authority implementation, signing keys, deployment credentials or content.

`schemas/` defines draft-2020-12 page, immutable release and license-envelope
formats. `src/` exposes TypeScript interfaces. `examples/` contains synthetic
fixtures only. `npm ci && npm test && npm run build` validates the initial package.

Schema validation is NOT license signature verification, membership authorization,
URL/path sanitization or module registry validation. Hosts must additionally
enforce unique region/block IDs, one semantic main region, 500 total blocks,
2 MiB body/depth limits, normalized paths, safe object keys, registered module
versions and each module's exact props schema. These semantic gates belong in
the private Core and release validator; the initial SDK does not claim them.

The package is marked private to prevent premature npm publication. Source
distribution/license terms and a public package release need owner approval.
The namespace and schema URLs are identifiers, not claims of deployed services.
